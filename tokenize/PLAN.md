# Plan: Speaker identification for quoted speech

## Purpose

The context lock (`it/PLAN.md §3`) requires knowing **who speaks** for each
quoted passage. Rather than re-deriving this implicitly during translation
(exactly the trap `it/PLAN.md §2` warns against), speaker identity is pinned
in a dedicated pre-processing step and stored in a committed file that feeds
the lock.

This step is a prerequisite for `it/PLAN.md §3`: the lock's `speaker` /
`addressee` fields cannot be filled without it.

## Input

`quotes/<canticle>.xml` — generated by `quotes.py`. One file per canticle; one
`<q>` element per quoted span. Each element carries:

| Attribute | Meaning |
|---|---|
| `id` | Stable line-anchored identifier, e.g. `10:77A` (canto:line + open-order suffix when multiple quotes start on the same line) |
| `line` | Line range of the span, e.g. `45-126` or `12` |
| `marker` | Delimiter pair: `«»`, `''`, or `""` |
| `head` | Leading tokens after the opener (only when `id` carries a suffix — disambiguation hint for the LLM) |

Nesting is expressed structurally: a `<q>` that contains child `<q>` elements
is an outer quote; its children are embedded quotes spoken within it.

The source canto files (`it/<canticle>/NN.txt`) are the ground truth and must
be consulted line by line alongside the XML.

To regenerate the XML:

```bash
uv run python quotes.py inferno purgatorio paradiso
```

## Output

`quotes/<canticle>.tsv` — one `id<TAB>speaker` row per `<q>`, beside the
generated `quotes/<canticle>.xml`. Committed to the repository; hand- and
LLM-edited. A hand-made sample of selected cantos lives in `quotes/ref/`.

```
id	speaker
2:10	Dante
2:45	Virgilio
2:58	Beatrice
```

The `speaker` value is the character's name **in the source spelling**
(`Virgilio`, not "Virgil"; `Frati Godenti`, not "Jovial Friars") — translation
adds no information and only burdens the local LLM downstream. Record the name
only, even for reported speech: the nesting structure in the XML already shows
who is quoting whom, so no `(quoted by …)` qualifier is needed. When the span
has no dramatic speaker — embedded scripture, Latin hymns, inscriptions, or
cited words — use the literal label `(none)`.

## Identification rules

Speaker attribution follows the verb of speaking in the surrounding narrative,
which in Italian is almost always adjacent to the quoted span:

1. **Dialogue verb in the same line or the immediately preceding/following
   line**: `disse`, `rispose`, `parlò`, `gridò`, `cominciai`, `cominciò`,
   `mi disse`, `diss' elli`, etc. The subject of that verb is the speaker.
2. **Verb omitted, attribution by turn-taking**: in rapid exchange (`Ed elli a
   me: «…»` / `E io: «…»`) the alternation between Dante and his interlocutor
   is the signal.
3. **Nested quotes**: the outer `«»` speaker attributes the inner `''` or `""`
   to whoever they are quoting — the inner speaker is the reported party, not
   the outer narrator. Record both:
   - outer `«»`: actual dramatic speaker (e.g. `Virgilio`)
   - inner `""`: reported speaker, by name only (e.g. `Beatrice`)
4. **Scripture / hymns / inscriptions / cited words**: no dramatic speaker;
   record `(none)`. Do not assign a biblical character as a live speaker — these
   are textual quotations, not dramatic speech.
5. **Periphrastic reference**: if the source names the speaker obliquely
   (`colui che…`, `l'anima…`), resolve the referent and record the proper
   name. The `id`-to-line mapping makes it fast to locate the passage and check
   the surrounding context.

## Validation

- Every `id` in the TSV must match an `id` in the current XML (stale ids
  signal a source change that needs review).
- Nested quotes must name the reported party, which is normally distinct from
  the outer speaker: if `2:45` is Virgilio, `2:58` (a child of `2:45`) names whom
  Virgilio reports — `Beatrice`. (A child may legitimately repeat the outer name
  when the speaker quotes themselves, as `2:76` does.)
- Cross-check against `it/ref/inferno-01.toml`: the hand-written context lock
  for Inferno Canto 1 already resolves speakers for that canto; the TSV entries
  for canto 1 must agree with it on *who* speaks. Note the lock currently uses
  English names (`Virgil`/`Dante`) while the TSV uses source spelling
  (`Virgilio`); agreement is about the person, not the string.

## Fit with the context lock (`it/PLAN.md §3`)

The TSV is a flat lookup table. When building a scene's TOML lock, the
`speaker` and `addressee` fields are populated by joining the scene's line
range against this table: any `<q>` whose span falls within the scene's lines
contributes its speaker to the lock. This join is mechanical; the intellectual
work (who speaks) is done once here and reused across all scenes.
